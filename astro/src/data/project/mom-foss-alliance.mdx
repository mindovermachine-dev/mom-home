## Problem

Modern software development depends on infrastructure that is often proprietary, surveilled, and difficult to leave. Vendor lock-in, opaque platforms, external legal reach, and AI services that may absorb code and data all limit the autonomy of developers and organisations.

Teams may want to reduce this dependency, but a credible alternative needs more than one self-hosted tool. It needs an integrated development stack: source control, CI, communication, reproducible development environments, and a deliberate way to use language models without handing the entire development process to a proprietary platform.

## Solution

MoM FOSS Development Stack is a practical alternative built from FOSS tools such as (but not limited to) VSCodium, Forgejo, Woodpecker CI, Matrix, reproducible development environments, and self-hosted language models. It can be self-hosted by organisations that want to operate their own stack, but the project also intends to run shared instances as part of the MoM infrastructure.

The stack is intended to make local development and CI/CD run the same verification and validation, while keeping code, data, communication, and AI-assisted work under the control of the people who use it. We intend to host the shared stack on servers geographically located in Denmark and build it in public through install parties, hackathons, and community projects.

## Value

MoM FOSS Development Stack gives developers and organisations a path toward greater control of their code, data, communication, and development environments. It aims to prove that a more independent and regenerative software ecosystem is possible, without treating digital autonomy as a purely theoretical ideal.

MoM FOSS Alliance members will get early access to the stack as it matures. The project is also intended as a practical place for members to influence priorities, contribute FOSS projects, and help shape the operating model.

## Status

The project is in its exploratory phase. We are defining the first stack, gathering collaborators, and starting with a small MVP using publicly available FOSS services where needed. The first aim is to demonstrate a useful, coherent subset before expanding into a fully hosted development platform.
